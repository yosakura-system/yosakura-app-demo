# 共有バックエンドのデプロイ手順（世桜システムのGoogleアカウントで）

これを一度やるだけで、**どの端末から報告しても全端末・本部で同じデータが見える**ようになります。無料です。
※ **世桜専用のGoogleアカウント**（例：`yosakura.fc@gmail.com` など、アプリと同じ運用アカウント）でやるのがおすすめです。

---

## 手順（10分ほど）

### 1. スプレッドシートを作る
1. Googleドライブで **新規 → Googleスプレッドシート** を作成。
2. 名前を「**世桜アプリ_データ**」などにする。
   （シート名 `reports` は自動で作られるので何もしなくてOK）

### 2. Apps Script を開く
1. そのスプレッドシートのメニュー **拡張機能 → Apps Script** をクリック。
2. エディタが開いたら、最初からある `function myFunction()...` を**全部消す**。

### 3. コードを貼る
1. 同じフォルダにある **`Code.gs` の中身を全部コピー**して、エディタに貼り付け。
2. 保存（フロッピーアイコン、または Ctrl+S）。

### 4. デプロイ（ウェブアプリとして公開）
1. 右上 **デプロイ → 新しいデプロイ**。
2. 歯車アイコン → 種類を **ウェブアプリ** に。
3. 設定：
   - **説明**：世桜アプリAPI（任意）
   - **次のユーザーとして実行**：**自分**
   - **アクセスできるユーザー**：**全員**（Anyone）
     ※ここが「全員」でないと、店舗のスマホから読み書きできません。
4. **デプロイ** をクリック。
5. 初回は **アクセスを承認** を求められる：
   - 「詳細」→「（安全ではないページ）に移動」→ アカウントを選んで **許可**。
   （自作スクリプトなのでこの警告は正常です）
6. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/......../exec`）を**コピー**。

### 5. URLを渡す
その **`/exec` で終わるURL**を神田までお知らせください。
アプリに接続して再公開します。これで同期が有効になります。

## ★写真を高画質化（Drive保存版）に更新する手順
写真を Google Drive に保存して高解像度化するには、Code.gs を最新版に差し替えて再デプロイします。

1. Apps Script エディタを開き、**既存のコードを全部消して**、最新の `Code.gs` を貼り直す → 保存。
2. **デプロイ → デプロイを管理 → 鉛筆（編集）→ バージョン「新規」→ デプロイ**（URLは変わりません）。
3. **今回は Google Drive への保存が加わるため、権限の再承認**を求められます。「詳細」→「移動」→ **許可**（Driveへのアクセスを許可）。
4. 完了したら「再デプロイした」と教えてください。アプリを高解像度送信に切り替えます。

※写真は Drive 内に「**世桜アプリ_写真**」フォルダが自動作成され、そこに保存されます。

## ★サーベイのライブ連携を有効にする手順（`SurveyImport.gs`）

各店のサーベイ転記スプレッドシートを**1時間ごとに自動で読み込み**、アプリへ反映します。
これまでは手作業で取り込んでいたため、元シートが更新されても反映されませんでした。

**前提：各店のサーベイスプレッドシートを、このGASのアカウントへ「閲覧者」以上で共有しておく**

### 1. ファイルを追加する
1. Apps Script エディタの左「ファイル」の **＋ → スクリプト**。
2. 名前を **`SurveyImport`** にする（`.gs` は自動で付きます）。
3. 同じフォルダの **`SurveyImport.gs` の中身を全部コピー**して貼り付け → 保存。
   ※ **`Code.gs` は変更しません**（既存の動作に影響しません）。

### 2. 読み込み先を設定する
1. 左の **⚙ プロジェクトの設定 → スクリプト プロパティ → プロパティを追加**。
2. **プロパティ名**：`SURVEY_SOURCES`
3. **値**：次の形（1行で貼って構いません）。店舗のぶんだけ並べます。

```
[{"store":"牛カツ世桜 長堀橋店","id":"スプレッドシートのID"},{"store":"日本料理世桜 心斎橋店","id":"スプレッドシートのID"}]
```

- `store` は**アプリの店舗名と完全に一致**させる（ここがずれると別店舗として集計されます）
- `id` はスプレッドシートURLの `/d/` と `/edit` の間の文字列
- シートを指定したいときは `"sheet":"フォームの回答 1"` を足す（省略すると1枚目）

### 3. 確認してから取り込む（この順番で）
1. 関数を **`validateSurveySources`** にして実行 → **どのシートが開けて、どの列が見つかったか**が出ます。
   「開けません」と出たら、まだ共有されていません。
2. 関数を **`surveyImportDryRun`** にして実行 → **何件入るかだけ**を確認（書き込みません）。
3. 問題なければ **`importSurveys`** を実行 → 取り込み。
4. 最後に **`setupSurveyImportTrigger`** を実行 → **1時間ごとの自動取り込み**が始まります。

※ 実行結果は「実行ログ」に日本語で出ます。止めたいときは `removeSurveyImportTrigger` を実行します。

### 補足
- **何度実行しても二重登録されません**（店舗＋回答時刻で判定しています）
- **列の順番が店舗ごとに違っても動きます**（見出しの文字で列を探します）
- **テスト投稿**（感想に「テスト」を含むもの）は国名に `TEST_` が付き、**アプリの集計から自動で外れます**。
  行自体は残るので、あとから確認できます
- 取り込んだ内容は `reports` シートに `kind = survey` として貯まります

## 補足
- **更新したとき**：Code.gs を直したら、**デプロイ → デプロイを管理 → 鉛筆 → バージョン「新規」→ デプロイ** で反映（URLは変わりません）。
- **データの中身**：スプレッドシートの `reports` シートに1行1報告で貯まります。ここを直接見れば生データを確認・編集・削除できます。
- **写真**：デモでは縮小サムネイル（1報告あたり最大3枚）をシートに保存します。将来フル解像度で残したい場合は Google Drive 保存に拡張できます。
- **プライバシー**：URLを知っていれば誰でも読み書きできる状態です（デモ用）。本番運用では、店舗ごとのトークンや簡易ログインで読み書きを制限する設計に拡張します。
